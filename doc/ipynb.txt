Installation                                                       *ipynb*

Add the lazy.nvim package spec, including when you use LazyVim: >lua
  { "WhiteHades/ipynb.nvim", lazy = false, opts = {} }
<
Run :Lazy sync and restart Neovim after installation. Use :IpynbInstall to
repair or update the runtime. Missing tools need confirmation and may need
sudo. For headless installation, run the printed setup command in a terminal.

The build requires Neovim 0.12+, uv 0.13.1+, Rust/Cargo 1.88+, Git, curl, tar,
pkg-config, a C/C++ compiler, and tree-sitter-cli 0.26.1+. Inline plots need
ImageMagick's magick command and a terminal such as Kitty or Ghostty.

To prepare a custom helper from the plugin checkout, run: >sh
  uv run --no-project --python ">=3.11" -- scripts/setup.py \
    --venv /path/to/helper/venv
<
To check host tools without installing them, run: >sh
  bash scripts/prerequisites.sh --check
<
Use --install to install missing tools, --yes to accept the plan, or
--no-images to skip ImageMagick. Sudo may still ask for a password.
The installer supports apt, dnf, pacman, and Homebrew. Pacman upgrades the
system. Rust installation may change the default toolchain to 1.88.0.
Put ~/.local/bin and ~/.cargo/bin on PATH before restarting Neovim.

Without lazy.nvim, install the dependencies in lazy.lua with your package
manager and put the plugin on runtimepath. Call require('ipynb').setup(opts),
install the markdown, markdown_inline, and python Tree-sitter parsers, then
run :IpynbInstall.

Run :checkhealth ipynb to check setup.

Configuration                                              *ipynb-options*

Set python to use an existing editor helper. For example:
>lua
  opts = {
    python = "/path/to/venv/bin/python",
    jupytext = "/path/to/venv/bin/jupytext",
    images = false,
    numpy_legacy_repr = true,
    keymaps = true,
    auto_init = false,
    auto_setup = true,
    output = { preview_lines = 10002 },
  }
<
Output shows up to 10,000 text rows by default, plus two border rows.
The 1,000,000 character limit also bounds unusually large output.

Python notebooks with a generic python3 kernel use the nearest project's
.venv. For standalone notebooks, the notebook directory is the project root.

Automatic project setup ~

auto_setup=true prepares the project's .venv on first execution. Standalone
notebooks get pyproject.toml, uv.lock, and .venv beside the notebook.
Setup uses uv and may need network access. Install plotting packages in the
project environment. To manage setup yourself, set auto_setup=false and
provide a .venv with ipykernel.

Kernel selection and language servers ~

kernel overrides automatic selection. Named notebook kernels and kernels for
languages other than Python use registered kernels. :IpynbInit opens a picker
with project Python and registered or shared kernels. Remote kernels and
connection files are also available. Local kernels start in the notebook's
project directory.

Completion and diagnostics use your existing Python language server. Pyright
and basedpyright use the selected local Python with separate project roots.
Set kernel_python to override the language server's Python interpreter.
Use kernel to select execution.

Set numpy_legacy_repr=true for NumPy's legacy="1.25" display in new local
Python kernels. Rerun cells to update saved output text.

Custom runtimes ~

Install requirements.txt into a custom helper before setting python.
Update those packages yourself. With build=false, run :IpynbInstall after
updates. Register other environments with ipykernel to select them explicitly.

Notebook appearance ~

With lazy.nvim, notebook prose uses your render-markdown.nvim settings when
that plugin is installed. Otherwise, notebooks use the included renderer.
Code and output share your theme's code background. Without one, they use a
darker Normal background, or stay transparent when Normal has no background.
Moving into a code cell does not change its background.

Code and output use thin terminal borders, with the normal editor background
between them. Plot sizes follow the terminal's cell size. Original images stay
unchanged.

Metadata uses a native fold with manual or expression folding. Normal movement
skips the summary. Use zo to edit metadata and zc to collapse it. Other fold
providers are left unchanged and show raw metadata.

Cell numbers and execution counts appear in the code border's right corner.
Your number, relativenumber, and statuscolumn settings remain unchanged.
Only visible running cells animate. Set vim.g.ipynb_animations = false to keep
static status labels. The spinner also respects vim.g.snacks_animate = false.

Saving                                                       *ipynb-saving*

:w saves code and outputs, including notebook metadata and attachments.
Normal mode shows one metadata line. Use zo to edit the full header.
Insert mode reveals the active cell's fences and language name for editing.
New outputs mark the notebook as unsaved. If a file changed elsewhere, resolve
the conflict before saving. See |ipynb-jupytext| for paired files.
After a failed load, writes stay blocked until a successful reload.
Recognizable Jupytext Markdown saved inside an .ipynb is recovered on opening.
The original bytes stay in a digest-named .bak beside it. Readonly opens do not
change the file. Unrecognized damaged files stay blocked rather than replaced.

Reopen a notebook to see saved outputs. A new or empty .ipynb starts with one
empty code cell. Save model checkpoints separately from notebook outputs.

The notebook uses normal save events and your existing autosave settings.
Each code cell runs your configured synchronous BufWritePre hooks in a buffer
with that cell's language and filename extension. Hidden language buffers are
reused for stateless hooks; stateful hooks get fresh buffers. Conform and attached
LSP formatters use their existing configuration and autoformat settings. A hook
error aborts the save. Asynchronous hooks that format after saving cannot change a
notebook that has already been written.

Otter maps LSP diagnostics to the notebook. Configured nvim-lint tools also run
on save. Tools that read stdin work with code in memory. Linters that need a file
require Otter's buffers.write_to_disk=true setting, which creates its normal
language files alongside the notebook. No formatter or linter is selected or
installed by ipynb.nvim.

Runtime                                                       *ipynb-rust*

Run :IpynbInstall after plugin updates, then restart Neovim. Set
binary="/path/to/ipynb-engine" to use a separately built engine.
Install optional Plotly, Kaleido, pnglatex, or CairoSVG renderers in the
helper environment when needed.

Kernels start on first execution. Set auto_init=true to start on opening.
If a kernel stops, run a cell to start a replacement. Earlier results stay
visible, but rerun cells needed to restore variables. :IpynbInfo shows the
interpreter, working directory, and selection reason.

Migration ~

Remove backend and IPYNB_DISABLE_RUST settings from older configurations.

Keys                                                           *ipynb-keys*

Existing mappings take precedence. Set keymaps=false to disable notebook keys.
The default <localleader> is a backslash. Modified Enter keys depend on your
terminal.

:Ipynb          Open the notebook action menu.
<localleader>n  Open the same menu.
<C-CR>          Run the cell.
<S-CR>          Run the cell and move to the next code cell.
<localleader>b  Insert a code cell below.
<localleader>m  Insert a Markdown cell below.
<localleader>s  Interrupt execution.
<localleader>r  Run the cell or visual selection.
<localleader>R  Run all cells.
<localleader>a  Run the cell and cells above it.
<localleader>o  Open and focus output. Normal Vim motions scroll the output.
<localleader>O  Close output. q and <Esc> also work in the output window.
<localleader>x  Open the first image in the terminal viewer.
<localleader>i  Restart the kernel, keeping outputs and clearing variables.

Commands                                                    *ipynb-commands*

:IpynbEnterOutput    Open and focus the full output.
:IpynbHideOutput     Close the full output.
:IpynbImagePopup     Enlarge the current cell's first image.
:IpynbOpenInBrowser  Open the current cell's HTML in a browser.
:IpynbYankOutput     Copy text output to the unnamed register.
:IpynbYankOutput!    Copy text output to the system clipboard.
:IpynbInterrupt      Interrupt execution.
:IpynbRestart        Restart the kernel.
:IpynbInfo           Show kernel information.
:IpynbJupytext       Open Jupytext formats and sync actions.

Use :IpynbInit to choose a kernel, as described in |ipynb-options|. For
installation and updates, see |ipynb|.

Jupytext                                                   *ipynb-jupytext*

:IpynbJupytext [action] supports info, export, pair, unpair, sync, pipe,
check, and cli. The notebook action menu has the same Jupytext submenu.
Choose a format in the picker and install any converter it requests. Put
project settings in jupytext.toml or [tool.jupytext] in pyproject.toml.

:w updates configured pairs unless a file changed externally. Use sync to
choose which source to keep when pairs differ. Unpair keeps the files. If a
paired save partly fails, check the error for files already saved.

Pipe changes require diff approval and stay unsaved until :w. Pipe and check
require an explicit command and stop after 20 seconds. The advanced CLI
terminal supports other upstream options, but its writes bypass editor
guards. Reload the notebook afterward.

Use Jupytext 1.19.6 or newer. Update custom helpers from requirements.txt.
See doc/jupytext.md for settings and workflows.

Images                                                        *ipynb-images*

Inline images fit within half the available width and 35% of the available
height. Their layout updates when terminal cell dimensions change. Images
remain visible when the editor loses focus; tmux visibility checks still keep
them in their owning session and window.
Use image.nvim's max_width and max_height to
limit image size, or output.height and output.width to cap the output window.
When the selected provider is snacks.nvim, inline output keeps image.nvim's
virtual placement support. Snacks renders images in floating output buffers.

With :set mouse=a, click an image in Normal or Insert mode to open only the
clicked image in a centered terminal viewer. :IpynbImagePopup and
<localleader>x open the first image in the current cell. The viewer fits
within 85% of the editor and resizes with the terminal. Close with q or <Esc>.
Existing mouse mappings take precedence. Other image providers use their own
popup viewers.

Click "More lines" to open the complete output or traceback. Alternatively,
use <localleader>o from the cell. Close the output window with q or <Esc>.
